# Changelog

All notable changes to Swidux are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased] — 1.7.0

### Changed
- **`Effect` is now `async throws`.** Reducers returning `{ send in … }` closures
  are unaffected (non-throwing closures convert implicitly), and effects can now
  `try await` directly. Code that *invokes* an `Effect` value — custom
  combinators, test harnesses — must add `try`. The store logs unhandled effect
  errors and ignores `CancellationError`.
- Re-entrant `Store.send` (from a reducer or plugin hook) is now deferred and
  run FIFO after the current cycle in all build configurations, instead of a
  DEBUG-only assertion with silent state clobbering in Release.
- `@Swidux`/`@Persisted` now emit compile errors for stored properties they
  previously skipped silently: missing type annotations (`var flag = false`)
  and combined declarations (`var a, b: Int`). Previously such properties reset
  on every dispatch (or never persisted) with no diagnostic.
- `CachedEntitlement` gains `cachedAt`; the persisted last-known-good key bumps
  to v2 with automatic one-shot migration. A stale cache (default 72 h) stops
  vouching for `isPro` but keeps `hasPermanentLicense`.
- The killswitch evaluates 1–2 component marketing versions (`"2.0"`) by
  padding them, instead of failing open forever; config-side versions remain
  strict `a.b.c`.
- Performance: the re-entrant dispatch queue drains with an index-based loop
  instead of repeated `removeFirst()` — O(k) instead of O(k²) for k deferred
  actions, still FIFO including actions appended mid-drain.
- Performance: `EntityDB.apply` fetches all touched rows in batches (chunks of
  500 IDs) via a macro-generated monomorphic `swiduxBatchFetchDescriptor(ids:)`
  instead of one fetch per write/deletion. Hand-written `PersistableModel`
  conformances (no generated batch descriptor) keep the per-ID path; transaction,
  rollback, and delete/reinsert semantics are unchanged.

### Added
- `EntityStore.remove(ids:)` — bulk deletion in a single pass with one index
  rebuild, recording deletions and cancelling pending upserts exactly like
  `store[id] = nil`. A subscript-delete loop costs O(n·k); prefer
  `remove(ids:)` or `removeAll(where:)` for multi-entity deletes.
- `PersistableModel.swiduxBatchFetchDescriptor(ids:)`, an optional requirement
  (defaulted to `nil`) generated by `@Persisted` for batched ID lookups.
- `Store.cancelEffects()` and automatic effect cancellation on store deinit —
  streaming effects no longer outlive the store.
- `ParentalGatePlugin` attempt limiting: consecutive wrong answers (default 3)
  start a cooldown (default 30 s); `.dismiss`/`.request` don't reset it.
- `ResilientPaywallService` retry backoff with jitter and cancellation support.
- `AnalyticsPlugin.flush(timeout:)` for shutdown paths where an unbounded wait
  risks the watchdog.
- `HTTPFeatureFlagsService` request timeout (`fetchTimeout`, default 10 s).
- `SemanticVersion.init(tolerant:)` for locally-sourced version strings.

### Fixed
- Deleting and re-inserting an entity in the same flush window (the shape of
  undo-of-delete) no longer destroys the row on disk — the reinsert now cancels
  the pending deletion at every layer.
- The killswitch blocker no longer renders a dead Update button when the remote
  config carries a URL scheme the plugin won't open.
- Clock-skew guards: a wall clock rolled backward no longer pins the killswitch
  to its cache or starves feature-flag refreshes.
- `@Inline` blob decode failures now log model and property before falling back
  to the default, instead of silently overwriting the old payload on next save.
- `SimulatedPaywallService` logs a fault at init in Release builds as an App
  Store submission tripwire.

## [1.6.0] — 2026-06-30
- Add `ResilientPaywallService`, a last-known-good entitlement decorator so a
  transient entitlement-read failure never presents a paid user as free (#41).

## [1.5.0] — 2026-06-18
- Feature flags: Keychain-backed bucketing identity + no-forever-flags
  governance (#40).
- Document all plugins and both companion packages (#39).

## [1.4.0] — 2026-06-11
- Fix pre-release audit findings across core and all plugins: HTTPS enforcement
  and 1 MB response caps on remote-config fetchers, transactional batch flushes
  (`EntityDB.apply`), surfaced persistence failures via `onFailure`, bounded
  undo depth, killswitch cache-freshness fixes, and more (#38).

## [1.3.0] — 2026-06-08
- Add first-class persistence: `@Persisted` macro + local and iCloud-sync
  plugins (#34).
- Make `@Persisted` CloudKit-safe: default values + optional relationships (#35).
- Gate Persnicket and swift-docc-plugin as dev-only tooling (#36).
- Fix `@Persisted` Release crash: generate monomorphic fetch descriptor (#37).

## [1.2.0] — 2026-05-29
- Add `SwiduxAnalytics` (mapper, auto-identify) and `SwiduxFeatureFlags`
  (flags + A/B variants + remote config) plugins (#16, #17).
- Add `KeyValueStore` with UserDefaults and Keychain backends (#14, #20, #21).
- Add `Store.binding(_:sending:)` (#18).
- Add vendor-free dev defaults for analytics & paywall, `.devPaywall` polish
  (#24, #27, #28).
- Add the shared multi-app Cloudflare ConfigWorker example (#25, #26).
- Rename macros: `@SwiduxState` → `@Swidux`, `@SwiduxNested` → `@Slice` (#15).
- Add Swidux logo and README badges (#33).

## [1.1.1] — 2026-05-05
- Fix DocC workflow for Swift 6.2 by targeting the macos-26 runner (#9).

## [1.1.0] — 2026-05-04
- Add the unified plugin system with killswitch, parental gate, and paywall
  plugins (#8).
- Add opt-in undo/redo middleware (#4).
- Add the Counter demo app (#3) and DocC documentation (#7).
- Simplify `Effect` to a typealias (#1).

## [1.0.0] — 2026-02-16
- Initial release: observable `Store`, pure reducers, async effects, the
  `EntityStore` changelog, and the persistence middleware pattern.
