# Swidux production hardening audit — 2026-09-05

Status: implementation and four rounds of independent review are complete. Debug and release tests, strict lint, iOS Simulator compilation, and the Counter macOS example build passed.

The audit inspected the store dispatch cycle, entity change tracking, persistence writers and SwiftData conversion, cancellation, plugin state transitions, remote configuration, analytics consent, and the package's existing tests. It found defects in the interaction between asynchronous operations as well as malformed-input handling.

| Priority | Confirmed defect | Change | Regression coverage |

## Intentional API changes

- Remove `PersistenceMiddleware` and `UndoMiddleware`; use `PersistencePlugin` and `UndoPlugin`.
- `Effect` becomes a value containing the operation and cancellation metadata. Construct work with `Effect { send in ... }` and lift actions with `effect.map(...)`, which preserves metadata. Top-level scopes register at dispatch; a scope created inside another effect becomes active only when invoked, so earlier cancellation does not target undeclared future work.
- Generated model construction, reconstruction, and update now throw. Direct callers must use `try`; `EntityDB` handles propagation and rollback.
- Generated inline properties are throwing read-only accessors. Update through the domain value and `update(from:)`.
- `Store.mutate` closures may escape during synchronous reentrancy so they can run after the current transaction commits.
- Parental-gate acceptance/rejection actions report an already-completed transition; submit answers through `.submitAnswer`.
- `EntityStore` enforces that subscript keys match entity IDs and `modify` preserves identity. Violations are programmer precondition failures.
- Entitlement snapshots expose live, cached, and provisional cache-seed provenance so bootstrap values cannot invalidate pending authoritative reads or renew cache freshness.
- `PaywallAction.refreshCancelled(requestID:)` is a plugin-owned completion notification. Its identity prevents delayed cancellation from finishing a newer request.

Independent review completed in four rounds. Round 1 found six blocking issues; round 2 found the provisional-cache ordering issue. Round 3 was clean. A subsequent integration check exposed shared-service request ordering and cancellation-cleanup defects, which were reproduced, fixed, and independently reviewed clean in round 4. The EntityStore identity invariant was verified separately. No findings were rejected and no fixes were reverted.

All confirmed audit blockers are resolved. The full debug and release suites and platform builds passed before a final test-only cleanup added nine explicit result discards in `StateWriterTests`. All 15 affected tests and strict lint passed after that cleanup, with no compiler warnings. Production source hashes remained unchanged; `git diff --check` passed. A focused release rerun was intentionally stopped when switching coverage configuration invalidated the optimized dependency cache. The original full-suite logs are preserved; the final test-only cleanup was verified in debug, not rebuilt in release.

Tests can establish the library's behavior under controlled interleavings and malformed inputs. They cannot certify a host app's signing, CloudKit entitlement setup, live cross-device delivery, or server-side purchase verification. Those require release-build integration checks in each shipping app. The package declares Swift 6.2, macOS 15, and iOS 18 minimums; this audit did not run a separate minimum-toolchain or minimum-OS test matrix.

Swift cancellation is cooperative, so a cancelled operation may still return a value; the keyed-effect output guard is required in addition to calling `cancel()`. See [Apple's Task cancellation documentation](https://developer.apple.com/documentation/swift/task/cancel()). Redirect decisions use the [URLSession task delegate](https://developer.apple.com/documentation/foundation/urlsessiontaskdelegate).
